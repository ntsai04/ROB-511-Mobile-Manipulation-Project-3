# Project 3 exam notes

Exactly **25 tests** live in `tests/test_project3.py`. The number in each test name matches this sheet. Each test is silent and reports only pass/fail through the course runner. Run one with `make test TESTS=test_project3.py::test_10_fixed_origin_translation_and_all_rpy_axes`.

Tests use the TCP interface only. The oracle in `checks.py` computes ordinary 4×4 matrices with independent Rodrigues rotations; it imports no project code. Every geometric case checks **both** `/tf` and `/xform_world`, exact frame membership, parent names, unit quaternions, column-major layout, the homogeneous bottom row, and the original joint-state stamp. Numerical comparisons allow `2e-5` per matrix element. Quaternion sign and publication order are ignored. Every case installs its own robot, explicitly publishes its configuration and root pose, and uses a unique stamp so older publications cannot satisfy it.

Diagnosis pattern: if 01–02 fail, fix parameter/protocol behavior before studying FK. If 10 passes and 11–15 fail, inspect joint motion math; if local edges look correct in Frame Lab while world poses fail, inspect RWSP tree composition. If failures follow a robot reload, inspect state replacement rather than a single numerical formula. Multiple mutations can cause several groups to fail.

The suite covers defined public behavior and avoids unspecified malformed graphs, nonfinite axes, out-of-limit configurations, optional FSM/servo behavior, and assumptions about transform order or quaternion sign. It is a diagnostic suite, not a reproduction of hidden autograder cases. Comments may be stripped in the challenge; keep this sheet separately as permitted.
